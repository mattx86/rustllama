# Intel oneAPI Runtime Redistributables

This document tracks the runtime DLLs the rustllama MSI installer
bundles alongside `rustllama.exe`. The list is regenerated by
running:

```cmd
cargo xtask stage-redist
```

which walks `%ONEAPI_ROOT%\compiler\latest\bin\` for the
manifest in [xtask/src/main.rs](../xtask/src/main.rs) (`REDIST_MANIFEST`),
copies the matched DLLs into `target/redist-staging/`, and prints
a markdown table of `(name, source path, size)` to paste below.

## Build vs. runtime

The full **oneAPI Base Toolkit** (~5 GB) is required to *build*
rustllama. Only the runtime DLLs below are required to *run* it.
The MSI ships them so end-users don't need to install oneAPI
separately.

## Pinned version

**oneAPI 2026.0** (the version used to produce the staged manifest
below). Earlier and later versions ship different filenames:

- **2025**: `sycl7.dll`, `pi_level_zero.dll`, `pi_opencl.dll`,
  `mkl_core.2.dll`, `mkl_sycl_blas.4.dll`, `mkl_tbb_thread.2.dll`
- **2026**: `sycl9.dll`, `ur_adapter_level_zero.dll`,
  `ur_adapter_opencl.dll`, `mkl_core.3.dll`, `mkl_sycl_blas.6.dll`,
  `mkl_tbb_thread.3.dll`

Glob patterns in the manifest absorb the MKL minor-version drift
(`mkl_core.*.dll` matches both `.2` and `.3`); SYCL major-version
drift needs a manifest edit (current pins `sycl9.dll` exact —
2025 hosts must swap to `sycl7.dll`).

## Procedure for an oneAPI version bump

1. Install the new oneAPI Base Toolkit. Set `%ONEAPI_ROOT%`.
2. Run `cargo xtask stage-redist --allow-missing` and read the
   "missing" report. Each line is either:
   - **Genuinely gone** in the new release (e.g. `pi_*` in 2026):
     drop from the manifest.
   - **Renamed**: add the new name(s) to the manifest.
3. Re-run `cargo xtask stage-redist` (without `--allow-missing`)
   to confirm a clean run.
4. Update the staged-DLL table below by copy-pasting the tool's
   markdown output.
5. Update the "Pinned version" section to call out the new
   release + any major filename changes.

## Group breakdown

- **SYCL runtime**: `sycl9.dll`, `ur_adapter_level_zero.dll`,
  `ur_adapter_opencl.dll`, `OpenCL.dll`, `intelocl64.dll` (~111 MB)
- **Intel C++ runtime**: `libmmd.dll`, `svml_dispmd.dll`,
  `libiomp5md.dll` (~27 MB)

The bulk is `intelocl64.dll` (109 MB, Intel's CPU OpenCL impl), which
provides the OpenCL fallback path when Level Zero is unavailable (some
integrated GPU configurations). The SYCL kernels are hand-rolled and
need no math-library redistributables.

## License

The Intel oneAPI runtime DLLs are redistributable under the
[Intel End User License Agreement for Developer Tools](https://www.intel.com/content/www/us/en/developer/articles/license/end-user-license-agreement.html).
The MSI bundle must include the EULA text — code-signing the
installer is a separate step that's tracked under the broader
"signed Windows distribution" item, not blocked by this manifest.

## Not bundled (and why)

- **`sycl-jit.dll`** (190 MB on 2026). The just-in-time compiler
  for SPIR-V → device IR. We compile kernels ahead-of-time with
  `icx -fsycl-targets=spir64_gen`, so JIT isn't required at
  runtime. If a future kernel pipeline switches to JIT, add this
  to the manifest (it'd push the bundle to ~580 MB).
- **Debug variants** (filenames ending in `d.dll` like
  `sycl9d.dll`, `mkl_sycl_blasd.6.dll`). Same purpose as the
  release builds, ~3× larger. The staging walker auto-excludes
  them via alphabetical-sort tiebreak.
- **`mkl_intel_lp64.*.dll`** (2025 manifest entry, gone in 2026).
  The LP64 interface is now bundled into `mkl_core.3.dll`.
